Chapter 9

Switch Statement

When you need to branch on many exact values of one variable, switch is cleaner than a long else if chain. This chapter covers every part of switch — cases, break, fallthrough, default, and when to use it over if/else.

5 Topics switch · case · break · fallthrough · default
Topic 1

Switch Syntax — Structure and How It Works

In Progress

Run this. Switch jumps directly to the matching case label — no comparison chain needed.

switch jumps to the matching case label like a table lookup

The switch statement evaluates one expression (which must produce an integer), then jumps directly to the case label that matches its value. If no label matches, it jumps to default (if one exists) or skips the block entirely.

This is not a series of comparisons — it is a direct jump. That is why switch is often faster than an equivalent else-if chain for many cases, and why the syntax looks different: you are labeling destinations, not writing sequential conditions.

Switch Structure
switch (expression) { case value_1: /* code for value_1 */ break; case value_2: /* code for value_2 */ break; default: /* runs if no case matched */ break; } /* expression must be integer type: int, char, enum */ /* case values must be compile-time integer constants */
💡
switch only works with integers
switch works with int, char, and enum — any integer type. It cannot be used with float, double, or strings. For those, use if/else.
🌍 Menu dispatch with switch

Switch is the natural structure for command dispatching — mapping a menu selection or event code to an action.

int choice = 2;

switch (choice) {
    case 1: printf("New file\n");    break;
    case 2: printf("Open file\n");  break;
    case 3: printf("Save file\n");  break;
    case 4: printf("Quit\n");       break;
    default: printf("Unknown\n");   break;
}

Topic 2

break — Why It Is Required in Every Case

In Progress

Run this first WITHOUT understanding it. Then look at what case 2 prints — it may be more than you expected.

Without break, execution falls through into the next case

After matching a case label, C starts executing code there and keeps going through all subsequent cases until it hits a break or the end of the switch block. This is called fallthrough.

break immediately exits the switch block. Without it, the code from the matched case and every case below it all execute — regardless of whether they matched. This is the most common switch bug for beginners.

With vs Without break
int x = 2; /* WITHOUT break — falls through */ switch (x) { case 1: printf("one\n"); /* skipped */ case 2: printf("two\n"); /* matched */ case 3: printf("three\n"); /* also runs! */ case 4: printf("four\n"); /* also runs! */ } /* prints: two, three, four */ /* WITH break — correct */ switch (x) { case 1: printf("one\n"); break; case 2: printf("two\n"); break; /* matched, then exits */ case 3: printf("three\n"); break; case 4: printf("four\n"); break; } /* prints: two */
⚠
Missing break is the #1 switch bug
Forgetting break compiles without error — the fallthrough is intentional C behavior. Always add break at the end of each case unless you explicitly want fallthrough.
🌍 break in practice

Every case in a properly-written switch ends with break, except intentional fallthrough (covered next) and the last case/default which can omit it.

int day = 3;
switch (day) {
    case 1: printf("Monday\n");    break;
    case 2: printf("Tuesday\n");   break;
    case 3: printf("Wednesday\n"); break;  /* prints this */
    case 4: printf("Thursday\n");  break;
    case 5: printf("Friday\n");    break;
    default: printf("Weekend\n");  break;
}

Topic 3

Intentional Fallthrough — When No break Is the Right Choice

In Progress

Run this. Multiple cases share one action intentionally — no break between them.

Fallthrough lets multiple case values share the same code

Omitting break between cases is sometimes deliberate. The most common use is grouping: stacking multiple case labels above one block of code so that any of those values trigger the same behavior. Each label has no code — it falls through immediately to the next case that does have code.

Always add a comment when doing this intentionally (/* fallthrough */) so that anyone reading the code knows it is deliberate, not a bug.

Intentional Fallthrough — Grouping Cases
int month = 4; int days; switch (month) { case 1: case 3: case 5: case 7: case 8: case 10: case 12: days = 31; /* all long months share this */ break; case 4: case 6: case 9: case 11: days = 30; /* all short months share this */ break; case 2: days = 28; break; } printf("%d days\n", days); /* 30 */
🌍 Grouping weekdays and weekend days

Intentional fallthrough is clean for mapping several values to the same category — like classifying day numbers into types.

int day = 6;  /* Saturday */
switch (day) {
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
        printf("Weekday\n");   break;
    case 6:
    case 7:
        printf("Weekend\n");   break;  /* prints this */
    default:
        printf("Invalid\n");   break;
}

Topic 4

default — Handling Unmatched Values

In Progress

Run this with different values and observe what happens when no case matches.

default catches everything that did not match any case

default is the switch equivalent of the final else. It runs when no other case label matches. It is optional — without it, unmatched values silently skip the entire switch block.

You should almost always include a default case. It catches unexpected values and gives you a place to handle errors or invalid input, rather than silently doing nothing.

default can be placed anywhere in the switch, but convention puts it last. It does not need a break unless you place it before other cases (rare).

default — Placement and Behavior
int code = 99; switch (code) { case 1: printf("Code 1\n"); break; case 2: printf("Code 2\n"); break; default: /* runs for any value not matched above */ printf("Unknown code: %d\n", code); break; } /* Without default: code=99 silently does nothing. With default: you handle it explicitly. */
💡
Always include default
Even if you think you have covered every possible value, add a default that prints an error. Values you did not expect will come up during debugging, and a silent skip is much harder to trace than an explicit message.
🌍 Default as an error handler

In production code, the default case is where you log unexpected states, print diagnostics, or set error flags — it is never just filler.

int status_code = 418;

switch (status_code) {
    case 200: printf("OK\n");           break;
    case 404: printf("Not Found\n");    break;
    case 500: printf("Server Error\n"); break;
    default:
        printf("Unhandled status: %d\n", status_code);
        break;
}

Topic 5

Switch vs else if — Choosing the Right Tool

In Progress

Run this — the same logic written two ways. Both produce identical output.

Use switch for exact integer values, else if for ranges and complex conditions

Use switch when: you are testing one variable against many exact constant values (case 1:, case 'A':). The code is cleaner and the intent is clearer than a long else if chain.

Use else if when: you need range checks (score >= 80), comparisons between multiple variables, or float/string conditions. switch cannot express any of these.

Decision Guide
/* Use SWITCH — exact integer/char values */ switch (error_code) { ... } switch (menu_choice) { ... } switch (letter_grade) { ... } /* Use ELSE IF — ranges, floats, complex logic */ if (score >= 90) ... /* range — switch cannot do this */ if (x > y) ... /* two-variable comparison */ if (price > 9.99) ... /* float — switch cannot use floats */ /* CANNOT use switch on: */ float f; switch (f) { } /* error: float not allowed */ char *s; switch (*s) { } /* comparing strings needs strcmp */
🌍 Mix both in one program

Real programs use switch and else if side by side — each for what it does best.

int command = 2;
int value   = 150;

switch (command) {           /* exact values — switch */
    case 1: printf("Set\n");    break;
    case 2: printf("Read\n");   break;
    default: printf("Bad\n");   break;
}

if (value >= 100) {          /* range check — else if */
    printf("High\n");
} else if (value >= 50) {
    printf("Medium\n");
} else {
    printf("Low\n");
}
