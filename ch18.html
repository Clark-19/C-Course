Topic 1

Dynamic Memory — malloc, calloc, free

In Progress

Run this. malloc allocates memory on the heap at runtime — compile and observe the array being built dynamically.

The stack is automatic; the heap is manual — malloc gives you heap memory

Every local variable goes on the stack — allocated when the function is called, freed when it returns. The heap is a separate memory pool: you request it with malloc, use it as long as you need, then release it with free. The key difference: the size can be a runtime value, not a compile-time constant.

malloc returns a void * — a raw address to the allocated block — or NULL if allocation failed. Always check for NULL before using the pointer. Every malloc must be paired with exactly one free; forgetting to free is a memory leak.

malloc, calloc, free
#include <stdlib.h> /* malloc — allocate n bytes, uninitialized */ int *arr = (int *)malloc(5 * sizeof(int)); if (arr == NULL) { /* allocation failed */ } /* calloc — allocate and zero-initialize */ int *zeroed = (int *)calloc(5, sizeof(int)); /* Use the memory */ arr[0] = 42; /* free — release when done (mandatory) */ free(arr); arr = NULL; /* good practice: nullify after free */
⚠
Every malloc must have exactly one matching free
Forgetting free is a memory leak — the process holds memory it will never use again. Calling free twice on the same pointer is undefined behavior and often crashes. Set the pointer to NULL immediately after freeing to prevent double-free bugs.
🌍 Real-world context

Dynamic arrays — where the size is read from user input or a file at runtime — are one of the most common uses of malloc. Every database engine, web server, and game engine allocates memory this way.

/* Read n from input, allocate exactly what's needed */
int n = getInputSize();
float *data = (float *)malloc(n * sizeof(float));
if (!data) { fprintf(stderr, "Out of memory\n"); exit(1); }
fillData(data, n);
processData(data, n);
free(data);

Topic 2

File Handling — fopen, fprintf, fclose

In Progress

Study this pattern. File I/O requires an OS filesystem — run this example locally with GCC to see it work. Compile here to study the syntax.

⚠
Browser limitation — file I/O runs locally only
The browser has no filesystem. The code below is correct C — it will not produce output here but will work when compiled with GCC. To run it: save as main.c → gcc main.c -o main → ./main. All quiz questions below test your understanding of the syntax and patterns.

Files give programs persistent memory — data survives after the program exits

A file in C is accessed through a FILE * pointer. fopen(filename, mode) opens the file and returns a pointer — or NULL if the file can't be opened. Always check for NULL. When done, fclose flushes buffers and releases the file handle — forgetting to close can corrupt the file.

File modes: "r" reads, "w" creates/overwrites, "a" appends, "r+" reads and writes. fprintf writes formatted text like printf. fgets reads a line safely (always bounds-checked, unlike fscanf).

File I/O Pattern
FILE *fp = fopen("data.txt", "w"); /* open for writing */ if (fp == NULL) { printf("Cannot open file\n"); return 1; /* exit with error */ } fprintf(fp, "Score: %d\n", 100); /* write to file */ fclose(fp); /* always close */ /* Reading */ FILE *fr = fopen("data.txt", "r"); char line[100]; fgets(line, sizeof(line), fr); /* read one line */ printf("%s", line); fclose(fr);
💡
fgets is safer than fscanf for reading strings
fscanf(fp, "%s", buf) stops at whitespace and can overflow the buffer. fgets(buf, sizeof(buf), fp) reads the whole line up to the buffer size limit — it cannot overflow, and it handles spaces correctly.

Study this write pattern. The browser compiler will not produce file output — run it locally with GCC to verify. Focus on the syntax structure.

🌍 Real-world context

Game save systems, configuration loaders, log writers — all use this exact pattern. The file acts as a key-value store that outlives the program.

/* Save game state */
FILE *save = fopen("save.dat", "w");
fprintf(save, "level=%d\n",    player.level);
fprintf(save, "health=%d\n",   player.health);
fprintf(save, "score=%d\n",    player.score);
fclose(save);

/* Load on restart */
FILE *load = fopen("save.dat", "r");
fscanf(load, "level=%d\n",  &player.level);
fclose(load);

Topic 3

Macros — #define Constants and Function Macros

In Progress

Run this. The preprocessor replaces every macro name before compilation — compile and see constants and function macros in action.

#define creates a text substitution — the preprocessor rewrites your code before compilation

A constant macro like #define MAX 100 causes the preprocessor to replace every occurrence of MAX with 100 before the compiler sees the code. No memory is used, no type is assigned. A function-like macro takes arguments: #define SQUARE(x) ((x)*(x)) expands to inline code wherever it is called.

Function-like macros have one critical rule: always wrap every argument and the whole expression in parentheses. Without them, SQUARE(a+b) expands to a+b*a+b — mathematically wrong. With parentheses: ((a+b)*(a+b)) — correct.

#define — Constants and Function Macros
/* Constant macro — replaces name with value */ #define PI 3.14159 #define MAX_SIZE 100 #define APP_NAME "MyApp" printf("Pi: %.5f\n", PI); /* → 3.14159 */ printf("Max: %d\n", MAX_SIZE); /* → 100 */ /* Function-like macro — always double-parenthesise */ #define SQUARE(x) ((x) * (x)) #define MAX(a,b) ((a) > (b) ? (a) : (b)) printf("%d\n", SQUARE(5)); /* → 25 */ printf("%d\n", MAX(3, 7)); /* → 7 */
⚠
Macros with ++ arguments are a classic bug
SQUARE(x++) expands to ((x++) * (x++)) — x is incremented twice. This is undefined behavior. Never pass an expression with side effects (like ++ or --) to a function-like macro. Use an inline function or a temporary variable instead.
🌍 Real-world context

Constant macros are the standard way to define physical constants, buffer sizes, magic numbers, and configuration values that appear throughout a codebase. A single #define change updates every usage instantly.

#define GRAVITY      9.81f
#define BUFFER_SIZE  4096
#define CLAMP(v,lo,hi)  ((v) < (lo) ? (lo) : (v) > (hi) ? (hi) : (v))

float speed  = velocity + GRAVITY * time;
char  buf[BUFFER_SIZE];
int   val = CLAMP(input, 0, 255);

Topic 4

Preprocessor — #ifdef, #ifndef, Include Guards

In Progress

Run this. The preprocessor chooses which code to compile based on what's defined — observe the conditional output.

Conditional compilation selects which code the compiler sees — the rest is erased before compilation

#ifdef NAME includes the block only if NAME has been #defined. #ifndef NAME is the opposite — includes if NOT defined. #endif closes the block. The compiler never sees the excluded code — it is completely removed by the preprocessor, not compiled to dead code.

The most important use of #ifndef is the include guard: a pattern every header file should use to prevent the same header from being included more than once, which causes duplicate declaration errors.

Conditional Compilation & Include Guard
/* Conditional compilation */ #define DEBUG #ifdef DEBUG printf("Debug: x = %d\n", x); #else /* release build — logging removed */ #endif /* Include guard (every header file needs this) */ #ifndef MYHEADER_H #define MYHEADER_H void myFunction(int x); int anotherFunction(void); #endif /* MYHEADER_H */
💡
Debug logging with #ifdef is zero-cost in release builds
Define a DEBUG_PRINT macro that uses printf when DEBUG is defined, and expands to nothing in release. Compile with gcc -DDEBUG program.c to turn it on without changing any source code. Release builds have no printf overhead at all.
🌍 Real-world context

Platform detection with preprocessor directives is universal in cross-platform C. The same source file compiles differently on Windows, Linux, and macOS — the preprocessor selects the right code for each target.

#ifdef _WIN32
    #include <windows.h>
    void clearScreen() { system("cls"); }
#elif defined(__linux__)
    #include <stdlib.h>
    void clearScreen() { system("clear"); }
#else
    void clearScreen() { printf("\n\n\n"); }
#endif
