Chapter 16

Pointers

A pointer is a variable that stores a memory address. That one sentence unlocks everything powerful in C — dynamic memory, passing by reference, array manipulation, data structures, and system-level programming. Every C programmer encounters pointers constantly. This chapter makes them concrete, visual, and manageable.

Topic 1

What is a Pointer?

In Progress

Run this. A pointer holds a memory address — print both the address and the value at that address.

A pointer is a variable that stores a memory address — not a value, a location

Every variable in C lives at a specific address in memory. A pointer is a variable whose value is one of those addresses. While an int x = 5 stores the number 5, a pointer int *p = &x stores the address where x lives in memory — like a mailing address vs the person who lives there.

Pointers are typed: int *p is a pointer to an int. The type tells the compiler how large the value at that address is and how to interpret the bytes stored there.

Memory Mental Model
/* Memory has addresses like street numbers */ int x = 42; /* x lives at address, say, 0x7fff1000 */ /* contents at 0x7fff1000: 42 */ int *p = &x; /* p stores the ADDRESS 0x7fff1000 */ /* p's own address might be 0x7fff1008 */ /* Two different things: */ printf("%p\n", (void*)p); /* the address stored IN p */ printf("%d\n", *p); /* the value AT that address = 42 */ /* Analogy: p = a piece of paper with an address written on it *p = going to that address and reading what is there &x = looking up x's address in the phone book */
💡
Pointers are just integers that happen to be addresses
On a 64-bit system, all pointers are 8 bytes regardless of what they point to. A pointer to int, char, or double is the same size — it is always just an address. The type determines how the computer interprets the memory at that address.
🌍 Where pointers appear in real C code

Pointers appear in function parameters, array operations, string handling, and dynamic memory. Understanding addresses is the foundation for all of these.

char name[] = "Alice";
char *p = name;        /* p points to name[0] */
printf("%s\n", p);     /* p works like the array name */

int arr[5] = {1,2,3,4,5};
int *ip = arr;         /* points to arr[0] */
printf("%d\n", *(ip+2)); /* reads arr[2] = 3 */

Topic 2

Declaring a Pointer — int *ptr

In Progress

Run this. Declaration syntax — the * in the declaration is NOT dereference, it is type syntax.

int *p declares p as a pointer-to-int — the * is part of the type, not an operator

The declaration int *p reads as "p is a pointer to int." The * in the declaration is type syntax — it is not the dereference operator. It means: "the thing at the address p holds is an int." The variable p itself always stores an address (typically 8 bytes on 64-bit systems).

Different base types require matching pointer types: char *cp points to a char, float *fp to a float. Mixing types — using a char* to read an int — produces undefined behavior (with the exception of void* which is a generic pointer to anything).

Pointer Declaration Patterns
/* type *name — pointer to type */ int *ip; /* pointer to int */ char *cp; /* pointer to char */ float *fp; /* pointer to float */ double *dp; /* pointer to double */ /* Declaration with initialization */ int x = 10; int *p = &x; /* p initialized to address of x */ /* COMMON MISTAKE: declaring two pointers */ int *a, b; /* a is int*, b is PLAIN int (not a pointer!) */ int *a, *b; /* both are pointers — write * before each name */ /* void* — generic pointer, points to anything */ void *vp = &x; /* valid but cannot dereference directly */
⚠
int *a, b — only a is a pointer, b is a plain int
The * binds to the variable name, not the type. In int *a, b, a is a pointer but b is a plain int. To declare two pointers: int *a, *b; — write the * before each name.
🌍 Function parameters as pointers

Function parameters that are pointers appear everywhere in C — the type tells the compiler what to expect at the address.

void process(int *data, int size) {
    /* data is a pointer to int — used like an array */
    for (int i = 0; i < size; i++)
        printf("%d ", data[i]);
}

Topic 3

Address-of Operator & — Getting a Variable's Address

In Progress

Run this. & returns the address where a variable lives in memory.

&x produces the memory address where x is stored

The unary & operator (address-of) applied to any variable returns a pointer — the memory address where that variable lives. &x produces a value of type int* if x is an int. This address is what you store in a pointer variable.

Every variable has an address. Even pointer variables have addresses (&p gives the address of the pointer itself — a pointer to a pointer, int**). You cannot take the address of a literal or expression that is not stored in memory: &42 is a compile error.

& — Address-of in Practice
int x = 10; char c = 'A'; float f = 3.14; /* &variable → pointer to that variable */ int *px = &x; /* px holds address of x */ char *pc = &c; /* pc holds address of c */ float *pf = &f; /* pf holds address of f */ /* Addresses vary each run — but relationships hold */ printf("x at %p\n", (void*)&x); printf("px = %p\n", (void*)px); /* Both print the same address */ /* Each variable is adjacent in memory (usually) */ int a=1, b=2, c2=3; printf("&a=%p &b=%p\n", (void*)&a, (void*)&b); /* b's address is typically 4 bytes above a's */ /* & used in scanf — you have used it already! */ /* scanf("%d", &x) passes the address of x so scanf can write the read value into x */
🌍 scanf uses & — you have used pointers from the start

Every scanf call passes an address. scanf needs to write into the caller's variable — passing the address gives scanf a way to reach it from inside the function.

int age;
scanf("%d", &age);   /* &age = address of age variable */
/* scanf writes the parsed integer to that address */
printf("You entered: %d\n", age);

Topic 4

Dereference Operator * — Reading and Writing Through a Pointer

In Progress

Run this. *p reads the value at the address stored in p — and writes to it too.

*p means "go to the address stored in p and read or write what is there"

The unary * operator (dereference or indirection) on a pointer gives you the value at the address the pointer holds. *p = 99 writes 99 to the variable p points to. int x = *p reads the value at p's address into x. Both operations affect the actual variable at that address — not a copy.

This is what makes pointers powerful: you can pass an address to a function, and the function uses *ptr to directly modify the caller's variable. The function has a reference to the original, not a copy.

* — Dereference Read and Write
int x = 5; int *p = &x; /* p points to x */ /* Read through pointer */ printf("%d\n", *p); /* 5 — value at address stored in p */ /* Write through pointer */ *p = 99; printf("%d\n", x); /* 99 — x was modified via *p */ /* * in different contexts — same character, different meaning */ int *q; /* declaration: q is pointer-to-int */ *q = 10; /* dereference: write 10 to address in q */ int r = *q; /* dereference: read value at q's address */ /* Double dereference (pointer to pointer) */ int **pp = &p; printf("%d\n", **pp); /* deref pp→p, deref p→x = 99 */
🌍 Writing through a pointer modifies the original

Dereferencing to write is how functions modify caller variables — give the function an address, it writes through the pointer to the original storage.

void setToZero(int *p) {
    *p = 0;     /* modifies the variable at address p */
}

int score = 100;
setToZero(&score);
printf("%d\n", score);   /* 0 — actually modified */

Topic 5

Pointer & Variable Relationship — How They Stay in Sync

In Progress

Run this. Changes via the variable and changes via the pointer affect the same memory — always in sync.

The pointer and variable share the same memory cell — changes through either are immediately visible through both

When p points to x, there is only ONE value in memory. Whether you read it as x or *p makes no difference — they are different names for the same byte(s). Modifying x = 99 is visible as *p == 99 immediately. Modifying *p = 77 is visible as x == 77 immediately. There is no copy involved.

You can point multiple pointers at the same variable, and all of them will see every change. This is called aliasing — two names for the same storage. It is powerful but requires careful thinking about who changes what and when.

Single Value, Multiple Names
int x = 10; int *p = &x; /* p and x share the same memory cell */ int *q = &x; /* q also points to x — three aliases */ x = 20; /* visible as *p==20 and *q==20 */ *p = 30; /* visible as x==30 and *q==30 */ *q = 40; /* visible as x==40 and *p==40 */ printf("x=%d *p=%d *q=%d\n", x, *p, *q); /* all print 40 — same cell */ /* p stores address, not value — changing what p points to */ int y = 99; p = &y; /* now p points to y, not x */ printf("x=%d *p=%d\n", x, *p); /* x unchanged (10 was last... actually 40); *p = y = 99 */
🌍 Two views of the same counter

In data structures and OS code, a pointer to a value is passed around so multiple components can observe and update the same counter or status field without copying.

int requests = 0;
int *counter = &requests;

/* Both increment the same variable */
requests++;          /* view A */
(*counter)++;        /* view B */
printf("%d\n", requests);   /* 2 */

Topic 6

NULL Pointer — The Safe "Points to Nothing" Value

In Progress

Run this. NULL is the safe "no address" value — always check before dereferencing.

NULL is address 0 — a conventionally invalid address that means "this pointer points to nothing"

NULL (defined in stddef.h and most standard headers) is the null pointer constant — address 0. No real object is stored at address 0 on any real operating system, so NULL serves as a sentinel value meaning "uninitialized" or "no target." Functions that return a pointer return NULL to signal failure.

Dereferencing a NULL pointer (*p when p == NULL) is always a program crash (segmentation fault). Before using a pointer you received from elsewhere, always check if (p != NULL). Initialize pointers to NULL when not yet assigned — better to crash predictably than to dereference garbage.

NULL — Safe Pointer Patterns
#include <stdio.h> /* Initialize to NULL when you don't have a target yet */ int *p = NULL; /* Safe check before use */ if (p != NULL) { printf("%d\n", *p); /* safe to dereference */ } else { printf("p is NULL — no target\n"); } /* Functions returning NULL to signal failure */ int arr[5] = {1,2,3,4,5}; int *found = NULL; for (int i = 0; i < 5; i++) { if (arr[i] == 3) { found = &arr[i]; break; } } if (found != NULL) printf("Found: %d\n", *found); else printf("Not found\n"); /* NULL in boolean context */ if (!p) printf("p is NULL\n"); /* !NULL is true */
⚠
Dereferencing NULL always crashes — check before dereferencing any pointer from outside
If a pointer was set by a function, returned from malloc, or passed as a parameter, treat it as potentially NULL until verified. if (ptr != NULL) before *ptr is not optional — it is required defensive programming.
🌍 NULL as a search result sentinel

Returning NULL from a search function cleanly communicates "not found" — the caller checks NULL before dereferencing, avoiding crashes.

int *findFirst(int arr[], int n, int target) {
    for (int i = 0; i < n; i++)
        if (arr[i] == target) return &arr[i];
    return NULL;   /* not found */
}

int data[] = {3,7,2,9};
int *result = findFirst(data, 4, 9);
if (result != NULL) printf("Found: %d\n", *result);
else                printf("Not found\n");

Topic 7

Pointer Arithmetic — Moving Through Memory

In Progress

Run this. Adding 1 to an int pointer advances by 4 bytes — one int forward, not one byte.

Pointer arithmetic scales by the pointed-to type — p+1 advances by sizeof(*p) bytes

When you add an integer to a pointer, C automatically scales by the size of the type: int *p; p+1 advances the address by sizeof(int) bytes (usually 4). This means p+1 points to the next int in memory, not the next byte. This is why pointer arithmetic works naturally with arrays — elements are adjacent and correctly sized.

Valid operations: p + n (advance n elements), p - n (retreat n elements), p++/p-- (advance/retreat one element), p1 - p2 (difference in element count between two pointers). You can also compare pointers with <, ==, etc. when they point into the same array.

Pointer Arithmetic — Element Steps
int arr[5] = {10,20,30,40,50}; int *p = arr; /* p points to arr[0] */ printf("%d\n", *p); /* 10 — arr[0] */ printf("%d\n", *(p+1)); /* 20 — arr[1] (advance 4 bytes) */ printf("%d\n", *(p+4)); /* 50 — arr[4] */ p++; /* p now points to arr[1] */ printf("%d\n", *p); /* 20 */ /* Pointer difference — how many elements apart? */ int *start = arr; int *end = arr + 5; /* one past last */ printf("%td elements\n", end - start); /* 5 */ /* arr[i] == *(arr + i) — always equivalent */ printf("%d == %d\n", arr[2], *(arr + 2)); /* 30 == 30 */
🌍 String traversal via pointer arithmetic

String processing in C often uses a pointer that walks forward through the string one character at a time — the same pattern as iterating an array.

char *s = "Hello, World!";
char *p = s;

while (*p != '\0') {
    if (*p == 'o') printf("o at offset %td\n", p - s);
    p++;   /* advance one char forward */
}
/* output: o at offset 4, o at offset 8 */

Topic 8

Pointers & Arrays — Two Sides of the Same Coin

In Progress

Run this. arr and &arr[0] are the same thing — both give you a pointer to the first element.

An array name decays to a pointer to its first element — arr[i] and *(arr+i) are identical

When you use an array name in most expressions, it decays to a pointer to its first element. arr and &arr[0] are the same address. Because of this, arr[i] is defined as *(arr + i) — bracket notation is just syntactic sugar for pointer arithmetic plus dereference.

When an array is passed to a function, it decays to a pointer — the function receives a pointer to the first element, not a copy of the array. This is why the function can modify the original array and why you must pass the size separately (the function cannot compute it from a pointer alone).

Array-Pointer Equivalence
int arr[5] = {10,20,30,40,50}; /* These are identical: */ arr[2] /* bracket notation */ *(arr + 2) /* pointer arithmetic + dereference */ *(2 + arr) /* addition is commutative! */ 2[arr] /* even this works (curiosity, not style) */ /* All print 30 */ printf("%d %d\n", arr[2], *(arr+2)); /* Passing to a function — decays to pointer */ void print(int *p, int n) { /* int *p and int p[] equivalent */ for (int i = 0; i < n; i++) printf("%d ", p[i]); } print(arr, 5); /* arr decays to &arr[0] */ /* sizeof difference — array vs pointer */ printf("array: %zu\n", sizeof(arr)); /* 20 bytes */ int *p = arr; printf("pointer: %zu\n", sizeof(p)); /* 8 bytes (address size) */
🌍 Functions that modify arrays — pass by pointer, modify directly

Passing an array to a function gives the function a pointer to the original. Changes inside the function immediately affect the caller's array — no return value needed.

void doubleAll(int *arr, int n) {
    for (int i = 0; i < n; i++) arr[i] *= 2;
}

int data[] = {1,2,3,4,5};
doubleAll(data, 5);
/* data is now {2,4,6,8,10} — modified in place */

Topic 9

Passing Pointers to Functions — Pass by Reference

In Progress

Run this. Pass the address — the function can read AND write the caller's variable through the pointer.

Pass &x to give a function write access to x — simulating pass-by-reference

C only has pass-by-value — functions receive copies. But by passing the address of a variable, you give the function a way to reach the original through pointer dereference. Inside the function, *ptr = value writes to the caller's variable. This pattern is called simulated pass-by-reference.

This is how multiple return values work in C: instead of returning two values, the function takes two pointer parameters and writes both results through them. It is also how scanf writes user input back to the caller's variables.

Pass by Pointer — Two Return Values
/* Function computes both quotient and remainder */ void divmod(int a, int b, int *quot, int *rem) { *quot = a / b; /* write to caller's quot variable */ *rem = a % b; /* write to caller's rem variable */ } int q, r; divmod(17, 5, &q, &r); /* pass addresses */ printf("%d / %d = %d remainder %d\n", 17, 5, q, r); /* 17 / 5 = 3 remainder 2 */ /* Swap — the classic pass-by-pointer example */ void swap(int *a, int *b) { int temp = *a; *a = *b; *b = temp; } int x = 10, y = 20; swap(&x, &y); /* pass addresses */ printf("%d %d\n", x, y); /* 20 10 — actually swapped */
🌍 min and max in one pass

Computing both minimum and maximum of an array in a single pass returns two values — pointer parameters make this clean.

void minmax(int *arr, int n, int *mn, int *mx) {
    *mn = *mx = arr[0];
    for (int i = 1; i < n; i++) {
        if (arr[i] < *mn) *mn = arr[i];
        if (arr[i] > *mx) *mx = arr[i];
    }
}

int data[] = {3,7,1,9,4};
int lo, hi;
minmax(data, 5, &lo, &hi);
printf("Min:%d Max:%d\n", lo, hi);  /* Min:1 Max:9 */

Topic 10

Modifying Caller Values — The Swap Pattern and Beyond

In Progress

Run this. Contrast by-value (no change) with by-pointer (changes original).

Pass the address to modify; pass the value to read — know which one you need

The core decision when writing a function: does the caller need the variable changed, or does it just need the value processed? Pass the value (int n) when the function only reads — simpler, safer, no accidental modification. Pass the address (int *p) when the function must modify the caller's variable.

Using const int *p (pointer to const int) is a middle ground: the function gets a pointer for efficiency (avoiding copy for large data) but the const prevents the function from modifying the value. This is the standard pattern for read-only pointer parameters.

Value vs Pointer Parameter — Decision Guide
/* Read only — pass value */ int square(int n) { return n * n; } /* Read only large data — pass const pointer */ int sumArr(const int *arr, int n) { int s = 0; for (int i = 0; i < n; i++) s += arr[i]; /* arr[i] = 0; ERROR — const prevents modification */ return s; } /* Modify caller's variable — pass pointer */ void increment(int *p) { (*p)++; } void clamp(int *p, int lo, int hi) { if (*p < lo) *p = lo; if (*p > hi) *p = hi; } int x = 5; increment(&x); /* x = 6 */ clamp(&x, 0, 4); /* x = 4 */ printf("%d\n", x); /* 4 */
🌍 In-place sorting — swap uses pointer parameters

Every sorting algorithm needs to swap elements. A swap function requires pointer parameters to actually exchange two values in the caller's array.

void swap(int *a, int *b) {
    int t = *a; *a = *b; *b = t;
}

int arr[] = {5,3,1,4,2};
/* Simple selection sort */
for (int i = 0; i < 4; i++)
    for (int j = i+1; j < 5; j++)
        if (arr[j] < arr[i]) swap(&arr[i], &arr[j]);

Topic 11

Common Pointer Mistakes — The Bugs That Crash Programs

In Progress

Run this. These are the four bugs that corrupt memory or crash programs — recognize each one.

The four pointer bugs that crash or corrupt every C program eventually

1. Uninitialized pointer dereference — int *p; *p = 5; — p holds garbage, writing to garbage address corrupts memory or crashes.

2. NULL pointer dereference — int *p = NULL; *p = 5; — dereferencing NULL is always a crash (segfault).

3. Dangling pointer — pointer to a variable that no longer exists (returned address of a local variable, or freed memory). Using it is undefined behavior.

4. Missing & in function call — passing x instead of &x to a function expecting a pointer makes the function treat the value as an address — garbage.

Four Pointer Bug Patterns
/* BUG 1: Uninitialized — p holds garbage address */ int *p; /* *p = 5; → CRASH or silent corruption */ int x = 0; p = &x; /* FIX: initialize before use */ /* BUG 2: NULL dereference */ int *q = NULL; /* *q = 5; → CRASH (segfault) */ if (q != NULL) *q = 5; /* FIX: check before deref */ /* BUG 3: Dangling pointer — local var gone */ int *bad() { int local = 42; return &local; /* local is destroyed at return! */ } /* FIX: never return address of local variable */ /* BUG 4: Missing & — value passed as address */ void setTo10(int *p) { *p = 10; } int n = 5; /* setTo10(n); → n's VALUE used as address → CRASH */ setTo10(&n); /* FIX: pass the ADDRESS */
⚠
Always initialize pointers — uninitialized is worse than NULL
An uninitialized pointer holds a random garbage address. Accessing it may succeed silently (hitting valid memory you happen to own) or crash unpredictably. NULL is better — it always crashes on access, making the bug obvious. Set every pointer to NULL if not immediately initialized.
🌍 Safe pointer usage checklist

Before using any pointer, run through this mental checklist — it prevents the four bugs above in almost all cases.

/* Safe pointer checklist:
   ✓ Is it initialized? (not garbage)
   ✓ Is it non-NULL? (check before deref)
   ✓ Does the target still exist? (no dangling)
   ✓ Is the type correct? (right pointer type)
   ✓ Is the index in bounds? (for pointer+n)
*/

int val = 42;
int *p = &val;              /* initialized */
if (p != NULL) *p += 1;     /* NULL-checked */
printf("%d\n", val);         /* 43 */
