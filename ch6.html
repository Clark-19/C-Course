Chapter 6

Type Conversion

C sometimes converts types for you automatically. Other times, you must convert them yourself with a cast. Knowing which is happening — and controlling it — fixes the most common calculation bugs in C.

5 Topics implicit · (type) cast · truncation
Topic 1

Implicit Type Conversion — What C Does Automatically

✅ Complete

Run this. Nobody told C to convert anything — but it did.

Implicit conversion happens automatically when C combines two different types in one expression. The compiler converts the less precise type to the more precise one before computing — you do not write anything extra.

The conversion ladder, from least to most precise: char → int → float → double. Whenever two different types meet, the lower one is *promoted* up before the operation runs.

Implicit Conversion — No Syntax Needed
int i = 5; float f = 2.5; float r = i + f; /* i silently becomes 5.0, then 5.0+2.5 = 7.5 */ double d = i + 1.0; /* i becomes 5.0, both become double: 6.0 */
🌍 Implicit conversion in sensor data

Mixing an int reading with a float calibration factor relies on implicit conversion constantly in embedded and sensor code.

int raw_reading = 512;
float calibration = 0.0048;
float voltage = raw_reading * calibration; /* int promoted to float */

Topic 2

Explicit Type Casting — (type) Syntax

✅ Complete

Run this. The cast forces a conversion the compiler would not do on its own.

An explicit cast is you telling C exactly what type to convert a value to, right now. The syntax is the target type in parentheses placed directly before the value: (float)x, (int)y.

Casts happen instantly, at that exact spot in the expression — useful for forcing float division, or deliberately truncating a value when you know that is what you want.

Cast Syntax
(int)3.9 /* → 3 (drops decimal) */ (float)7 /* → 7.0 */ (double)x /* widens x to double precision */ int a = 10, b = 3; float r = (float)a / b; /* forces float division: 3.333... */
💡
Remember
The cast applies only to the value immediately after it. (float)a / b casts only a — but that's enough, because b then gets promoted automatically.
🌍 Casting in financial calculations

Percentage calculations always need an explicit cast to avoid the integer-division trap.

int budget_used = 340, budget_total = 500;
float pct = (float)budget_used / budget_total * 100;
printf("%.1f%% used\n", pct);

Topic 3

Integer to Float Casting — Fixing Division Problems

✅ Complete

Run this. Compare the three average calculations.

The classic bug: int total = 17; int count = 3; float avg = total/count; gives 5.0, not 5.666.... The division happens as integer math first, before the result is ever stored as float.

The fix is always the same: cast one operand to float before the division operator runs. (float)total / count — not after.

The Standard Fix Pattern
int total = 17, count = 3; float avg_wrong = total / count; /* 5.0 — integer division */ float avg_right = (float)total / count; /* 5.67 — correct! */
🌍 Grade averages depend on this fix

Every grading system, statistics tool, and analytics dashboard relies on this exact cast pattern to avoid silently wrong averages.

int scores_sum = 268, num_tests = 3;
float average = (float)scores_sum / num_tests;
printf("Average: %.2f\n", average); /* 89.33 */

Topic 4

Float to Integer Casting — Truncation Behavior

✅ Complete

Run this. Watch what happens to 9.99 and -9.99 when cast to int.

Casting float to int does not round — it truncates, chopping off everything after the decimal point. (int)9.99 gives 9, not 10.

Truncation always moves toward zero: (int)-9.99 gives -9 (not -10). This is different from "round down" — it rounds toward zero regardless of sign.

To round to the nearest integer instead of truncating, add 0.5 before casting a positive number: (int)(x + 0.5).

Truncation vs Rounding
(int)9.99 → 9 /* truncates, not rounds */ (int)9.01 → 9 (int)-9.99 → -9 /* toward zero, not down */ /* Manual rounding for positive numbers */ float x = 9.6; int rounded = (int)(x + 0.5); /* → 10 */
⚠
Common Mistake — Assuming Casts Round
Beginners often expect (int)4.9 to give 5. It gives 4. C never rounds during a cast — it always truncates.
🌍 Truncation in pagination

Calculating how many full pages are needed for a set of items relies on intentional truncation, then adding 1 if there's a remainder.

int items = 47, per_page = 10;
int full_pages = items / per_page;       /* truncates: 4 */
int extra = (items % per_page != 0) ? 1 : 0;
int total_pages = full_pages + extra;    /* 5 */

Topic 5

Common Casting Mistakes — and How to Avoid Them

✅ Complete

Run this. It looks like it should give a decimal — but it does not.

The most common casting mistake: casting the result instead of an operand. (float)(a/b) casts after the integer division already happened — too late. (float)a/b casts before — correct.

Second mistake: forgetting that storing a float into an int variable is itself a truncating cast, even without writing (int) explicitly. int x = 7.9; silently truncates to 7.

Wrong vs Right Placement
int a = 7, b = 2; float wrong = (float)(a / b); /* a/b=3 first (int), THEN cast → 3.0 */ float right = (float)a / b; /* a cast to float FIRST → 3.5 */ /* Implicit truncation — no (int) written but it still truncates */ int x = 7.9; /* x = 7, silently */
⚠
Common Mistake — Casting Too Late
Always ask: "has the integer math already happened by the time I cast?" If yes, the cast is too late to fix anything.
🌍 Cast placement bugs in production

Misplaced casts are a classic code-review finding — they compile fine and look correct, but silently produce wrong numbers.

/* Found in a real bug report: discount showed as 0% */
int saved = 0, original = 50;       /* item is free: saved=0 */
float pct = (float)(saved/original); /* 0/50=0 first, then cast: 0.0 */
/* fix: */
float pct_fixed = (float)saved/original; /* still 0.0 here, but pattern matters when saved>0 */
