Topic 1

Local vs Global Variables

In Progress

Run this. One variable is global — accessible everywhere. The other is local — trapped inside one function.

Local variables belong to one function. Global variables belong to the entire program.

A local variable is declared inside a function or block. It is created when that function is called and destroyed when it returns. No other function can see or touch it.

A global variable is declared outside all functions, at the top of the file. It lives for the entire program lifetime and can be read or modified by any function in the file. While convenient, uncontrolled global state is a common source of bugs — any function can change it at any time.

Local vs Global
int globalCount = 0; /* global — visible to all functions */ void increment() { globalCount++; /* accesses the global */ int localTemp = 5; /* local — only exists here */ } void show() { printf("%d\n", globalCount); /* global is accessible */ /* printf("%d\n", localTemp); ERROR — localTemp not visible here */ } /* Best practice: prefer local variables, use globals sparingly. Global state makes programs harder to reason about. */
⚠
Globals are not inherently wrong — but they are risky
Global variables seem convenient but any function anywhere can modify them, making bugs hard to trace. Prefer passing values as parameters and returning results. Reserve globals for constants or truly program-wide state.
🌍 Configuration values — one legitimate use of globals

Constants and configuration values that the entire program needs are acceptable as globals — especially when declared const so nothing can accidentally modify them.

const int MAX_USERS = 100;   /* global constant — read-only */
const float TAX_RATE = 0.12;

void printTax(float price) {
    printf("Tax: %.2f\n", price * TAX_RATE);  /* reads global */
}

Topic 2

Scope Rules in C — Blocks, Nesting, Shadowing

In Progress

Run this. A variable declared inside a block only lives in that block. Trace each x carefully.

Every set of curly braces creates its own scope — inner scopes can shadow outer ones

A block scope is created by any pair of curly braces { } — a function body, an if statement, a for loop, even a standalone block. Variables declared inside a block are inaccessible once the block ends.

Shadowing occurs when an inner block declares a variable with the same name as an outer one. Inside the inner block, the name refers to the inner variable — the outer one is hidden. This compiles without errors but is a common source of confusion. Most style guides forbid it.

Block Scope and Shadowing
int x = 10; /* outer x */ { int x = 20; /* inner x — SHADOWS outer */ printf("%d\n", x); /* 20 — inner x */ } printf("%d\n", x); /* 10 — outer x is back */ /* for loop variable scoped to the loop */ for (int i = 0; i < 3; i++) { /* i lives here */ } /* i does not exist here */ /* Shadowing in if blocks */ if (1) { int result = 42; /* only inside this if */ printf("%d\n", result); } /* result does not exist here */
💡
Avoid shadowing — use different names
Shadowing is valid C but confusing to read. When an inner variable shares a name with an outer one, readers must carefully track which one each reference means. Use distinct names across scopes to make code unambiguous.
🌍 Loop-local variables — prevent accidental reuse

Declaring variables as close to their use as possible — inside the block that needs them — prevents accidental reuse across loop iterations and keeps intent clear.

for (int i = 0; i < 5; i++) {
    int doubled = i * 2;   /* fresh each iteration */
    printf("%d\n", doubled);
}
/* doubled and i do not pollute the outer scope */

Topic 3

Storage Classes — auto, extern, register, const

In Progress

Run this. const prevents modification. Observe the different storage class behaviors.

Storage classes control where a variable lives in memory and how long it lives

Every variable in C has a storage class that determines its lifetime, scope, and memory location. The most common are: auto (default for locals — stack, function lifetime), static (persists between calls — covered in Topic 4), extern (declared elsewhere, used here), and const (read-only value).

In modern C, auto is implicit and never written explicitly. const is important — it tells the compiler and future readers that this value must not change. Using const for fixed values prevents accidental modification and enables compiler optimizations.

Storage Class Keywords
/* auto — implicit default, never written */ int x = 5; /* same as: auto int x = 5; */ /* const — read-only, value cannot change */ const int MAX = 100; const float PI = 3.14159; /* MAX = 200; → COMPILE ERROR */ /* extern — variable defined in another file */ /* extern int sharedCount; */ /* register — hint to store in CPU register (advisory) */ /* register int fast = 0; */ /* const parameters — protect what is passed in */ void printValue(const int n) { printf("%d\n", n); /* n = 99; → COMPILE ERROR inside function */ }
💡
Use const for any value that should not change
Declare magic numbers and fixed values as const variables rather than raw literals. const int DAYS_IN_WEEK = 7; is better than using 7 throughout your code — it names the intent and prevents accidental modification.
🌍 Named constants replace magic numbers

Every program has fixed values — screen sizes, limits, rates. Naming them with const makes the code self-documenting and changes propagate everywhere automatically.

const int BOARD_SIZE  = 8;
const int MAX_PLAYERS = 4;
const float WIN_RATE  = 0.75;

for (int r = 0; r < BOARD_SIZE; r++) {
    for (int c = 0; c < BOARD_SIZE; c++) {
        /* process board[r][c] */
    }
}

Topic 4

static Variables — Memory That Persists Between Calls

In Progress

Run this. A static variable inside a function keeps its value between calls — unlike a normal local.

static locals are initialized once and keep their value forever

A static local variable is different from a normal local in two key ways: it is initialized only once (the first time the function runs, not on every call), and its value persists between calls — the variable is not destroyed when the function returns.

This makes static locals perfect for call counters, memoization, and state machines — any case where a function needs memory of previous invocations without the risk of a global variable.

static Local — Persists Between Calls
void callCounter() { static int count = 0; /* initialized ONCE, persists */ count++; printf("Called %d time(s)\n", count); } callCounter(); /* Called 1 time(s) */ callCounter(); /* Called 2 time(s) */ callCounter(); /* Called 3 time(s) */ /* Compare to normal local: */ void normalCounter() { int count = 0; /* reset to 0 EVERY call */ count++; printf("Count: %d\n", count); /* always prints 1 */ } /* static variables are scoped to their function but have program lifetime (like globals). */
🌍 Generating unique IDs without a global

A static counter inside a function gives each call a unique number without exposing global state — the counter is private to the function but persists across all calls.

int nextId() {
    static int id = 0;
    return ++id;
}

printf("ID: %d\n", nextId());   /* ID: 1 */
printf("ID: %d\n", nextId());   /* ID: 2 */
printf("ID: %d\n", nextId());   /* ID: 3 */

Topic 5

The Standard Library — What C Gives You for Free

In Progress

Run this. These functions come from stdlib.h and string.h — no code needed to write them.

The C standard library provides tested, portable functions via header files

C ships with a standard library — a collection of pre-written functions grouped by purpose into header files. You include the header to access its functions. The most used headers are: stdio.h (input/output — printf, scanf), stdlib.h (general utilities — abs, rand, malloc), string.h (string operations — strlen, strcpy, strcmp), math.h (mathematics — sqrt, pow, floor), and ctype.h (character testing — isdigit, isalpha, toupper).

These functions are implemented by your C runtime environment and are as fast as anything you could write manually. Always check if the standard library has what you need before writing it from scratch.

Key stdlib Functions
/* stdlib.h */ #include <stdlib.h> abs(-7) /* → 7 — absolute value of int */ rand() /* → random int 0 to RAND_MAX */ rand() % 6 + 1 /* → random 1–6 (dice) */ /* string.h */ #include <string.h> strlen("hello") /* → 5 — number of chars */ strcmp("a","b") /* → negative (a < b alphabetically) */ strcmp("a","a") /* → 0 (equal) */ /* ctype.h */ #include <ctype.h> isdigit('5') /* → non-zero (true) */ isalpha('A') /* → non-zero (true) */ toupper('a') /* → 'A' */ tolower('Z') /* → 'z' */
🌍 Classifying characters from user input

Parsing input character-by-character is common in C — ctype.h functions classify each character cleanly without manual ASCII range checks.

#include <ctype.h>
char ch = 'A';
if (isalpha(ch))  printf("letter\n");
if (isupper(ch))  printf("uppercase\n");
if (isdigit(ch))  printf("digit\n");
printf("%c\n", tolower(ch));   /* a */

Topic 6

math.h — Square Roots, Powers, Rounding

In Progress

Run this. math.h gives you every mathematical operation C's arithmetic operators cannot express.

math.h provides the mathematical operations that C operators cannot express

C's built-in operators (+ - * / %) cover basic arithmetic. math.h adds everything else: sqrt(x) for square root, pow(x, y) for x to the power y, floor(x)/ceil(x)/round(x) for rounding, fabs(x) for absolute value of doubles, and the trigonometric family.

All math.h functions work with double (not int). Passing an integer is fine — C promotes it automatically. But the return value is always double — store results in a double variable or cast explicitly if you need an integer.

math.h — Essential Functions
#include <math.h> sqrt(25.0) /* → 5.0 — square root */ pow(2.0, 10.0) /* → 1024.0 — 2 to the power 10 */ fabs(-3.7) /* → 3.7 — absolute value (double) */ floor(4.9) /* → 4.0 — round DOWN */ ceil(4.1) /* → 5.0 — round UP */ round(4.5) /* → 5.0 — round to nearest */ /* Common use: distance formula — sqrt(dx²+dy²) */ double dx = 3.0, dy = 4.0; double dist = sqrt(dx*dx + dy*dy); /* 5.0 */ /* Primality: only check divisors up to sqrt(n) */ for (int d = 2; d <= (int)sqrt(n); d++) { ... }
🌍 Hypotenuse and distance calculations

The Pythagorean theorem appears in game physics, mapping, and graphics. sqrt and pow from math.h compute distances cleanly and correctly for floating-point coordinates.

#include <math.h>
double distance(double x1,double y1,double x2,double y2){
    double dx = x2 - x1;
    double dy = y2 - y1;
    return sqrt(dx*dx + dy*dy);
}
printf("%.2f\n", distance(0,0,3,4));  /* 5.00 */
printf("%.2f\n", distance(1,1,4,5));  /* 5.00 */

Topic 7

Recursion — The Call Stack in Depth

In Progress

Run this. Watch how recursive calls stack up and then unwind in reverse.

Each recursive call creates a new stack frame — frames unwind in reverse on return

Every function call — including recursive ones — pushes a new stack frame onto the call stack. This frame holds the function's local variables and parameters independently of other frames. Recursive calls stack up frames; when the base case returns, frames unwind one by one, each returning to its caller.

Code before the recursive call runs on the way down (as frames are created). Code after the recursive call runs on the way back up (as frames unwind). This is why placing printf before or after the recursive call produces reversed outputs.

Down vs Up — Call Order vs Return Order
void down(int n) { if (n == 0) return; printf("%d ", n); /* runs going DOWN — before recursive call */ down(n - 1); } down(3); /* prints: 3 2 1 */ void up(int n) { if (n == 0) return; up(n - 1); printf("%d ", n); /* runs going UP — after recursive call returns */ } up(3); /* prints: 1 2 3 */ /* Same function, same calls — order of printf vs recursion determines whether you print on the way down or up */
🌍 Reversing a number with the call stack

The call stack naturally reverses sequences. Printing digits after the recursive call uses the stack's LIFO (last-in, first-out) order to print digits from least-significant to most-significant — reversing the number.

void reverseDigits(int n) {
    if (n == 0) return;
    printf("%d", n % 10);   /* print this digit on the way UP */
    reverseDigits(n / 10);  /* recurse on remaining digits */
}
reverseDigits(1234);  /* prints: 4321 */

Topic 8

Base Case & Recursive Case — Writing Correct Recursion

In Progress

Run this. The function has two clear sections — the stop and the continue. Identify both.

Design recursion by defining the base case first, then the recursive step

When writing a recursive function, always start with: what is the simplest possible input and what should the answer be? That is your base case. Then ask: given a larger input, how can I reduce it to a simpler sub-problem? That is your recursive case. The reduction must always move toward the base case — otherwise you get infinite recursion.

Multiple base cases are common. fibonacci(0) = 0 and fibonacci(1) = 1 are both base cases. For defensive programming, also guard against invalid inputs (negative numbers, null pointers) at the top of the function.

Template for Writing Recursive Functions
int solve(int n) { /* Step 1: guard against invalid input */ if (n < 0) return -1; /* Step 2: base case(s) — stop here, return directly */ if (n == 0) return 0; if (n == 1) return 1; /* Step 3: recursive case — reduce and combine */ return solve(n - 1) + solve(n - 2); } /* Key checklist: ✓ Does every path hit a base case eventually? ✓ Does the recursive call use a SMALLER/SIMPLER input? ✓ Are ALL base cases handled? ✓ Is the combination step (+ - * etc.) correct? */
🌍 Binary search — recursion naturally maps to divide-and-conquer

Binary search on a sorted array cuts the search space in half each call — a textbook recursive reduction. The base case is when the search space is empty or the element is found.

int bsearch(int arr[], int lo, int hi, int target) {
    if (lo > hi) return -1;          /* base: not found */
    int mid = (lo + hi) / 2;
    if (arr[mid] == target) return mid; /* base: found */
    if (arr[mid] < target)
        return bsearch(arr, mid+1, hi, target); /* right half */
    return bsearch(arr, lo, mid-1, target);     /* left half */
}

Topic 9

Factorial & Fibonacci — Classic Recursive Algorithms

In Progress

Run both. They are the two most studied recursive algorithms — understand how each works.

Factorial is a clean single recursion — Fibonacci has two, making it exponentially slow

Factorial: n! = n × (n-1)! — one recursive call per step, so it takes exactly n calls. Simple, elegant, and efficient recursively.

Fibonacci: fib(n) = fib(n-1) + fib(n-2) — two recursive calls per step. Each of those makes two more. The total calls grow exponentially: fib(30) makes over a million recursive calls. This is why recursive Fibonacci is a teaching example but never used in production — the iterative version (or memoized version) is vastly faster.

Factorial vs Fibonacci — Recursive Cost
/* Factorial — O(n) calls, fine recursively */ int factorial(int n) { if (n <= 1) return 1; return n * factorial(n - 1); } /* Fibonacci recursive — O(2^n) calls, SLOW */ int fib_slow(int n) { if (n <= 1) return n; return fib_slow(n-1) + fib_slow(n-2); } /* Fibonacci iterative — O(n), always prefer this */ int fib_fast(int n) { if (n <= 1) return n; int a = 0, b = 1; for (int i = 2; i <= n; i++) { int t = a + b; a = b; b = t; } return b; }
🌍 Combinations in statistics — uses factorial

Combinations (choosing k from n) are defined using factorials. Calling factorial() three times gives the answer directly — readable code that matches the mathematical formula exactly.

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

int choose(int n, int k) {
    return factorial(n) / (factorial(k) * factorial(n - k));
}

printf("C(5,2) = %d\n", choose(5, 2));   /* 10 */
printf("C(6,3) = %d\n", choose(6, 3));   /* 20 */

Topic 10

Recursion vs Iteration — When to Use Each

In Progress

Run both versions — same output, different approaches. Compare the code structure.

Prefer iteration for performance — prefer recursion when the problem is naturally recursive

Iteration (loops) is generally faster: no stack frame overhead, no risk of stack overflow, and the compiler can optimize loops aggressively. For problems with a simple counter — summing, searching, processing arrays — iteration is the right choice.

Recursion shines when the problem is recursive by nature: tree traversal, divide-and-conquer algorithms, parsing nested structures. The code mirrors the problem definition directly. Forcing iteration on these problems produces complex, harder-to-understand code. The rule: use recursion when the recursive solution is clearer, and the depth is bounded and reasonable.

Recursion vs Iteration — Decision Guide
/* Use iteration: simple count, known range */ int sumIter(int n) { int total = 0; for (int i = 1; i <= n; i++) total += i; return total; } /* Use recursion: naturally recursive structure */ int sumRec(int n) { if (n <= 0) return 0; return n + sumRec(n - 1); } /* Both give the same result but: Iteration: O(n) time, O(1) space — no stack frames Recursion: O(n) time, O(n) space — n stack frames For n=1000, iteration is safer. For tree/nested structures, recursion is clearer. */
💡
Every recursion can be converted to iteration — and vice versa
The two approaches are always interchangeable in theory. Recursion uses the implicit call stack; iteration uses an explicit stack or counter. Choose based on clarity and safety — if recursion depth could be large (thousands of levels), use iteration instead to prevent stack overflow.
🌍 Power function — both versions, one clear winner

Computing a^n iteratively is more efficient for large exponents — no stack overhead. But the recursive version reads like the mathematical definition exactly. Know both; choose based on context.

/* Iterative — O(n), O(1) space */
int powerIter(int base, int exp) {
    int result = 1;
    for (int i = 0; i < exp; i++) result *= base;
    return result;
}

/* Recursive — O(n), O(n) stack */
int powerRec(int base, int exp) {
    if (exp == 0) return 1;
    return base * powerRec(base, exp - 1);
}

printf("%d %d\n", powerIter(2,8), powerRec(2,8)); /* 256 256 */
