Topic 1

Booleans in C — Zero and Non-Zero

In Progress

Run this first. C has no built-in true or false keyword — watch what it uses instead.

C has no true/false — it uses integers

In C, any integer that is 0 means false. Any non-zero integer means true — including negative numbers. There is no boolean type built into classic C (C89/C90). When you write if (x), C checks if x is non-zero.

This matters because comparison operators (==, <, etc.) return 1 for true and 0 for false — plain integers. Knowing this helps you understand why if (5 > 3) works: 5 > 3 evaluates to the integer 1.

Boolean Values in C
/* FALSE: only zero */ 0 /* false */ /* TRUE: anything non-zero */ 1 /* true */ -1 /* also true */ 42 /* also true */ 0.1 /* also true (non-zero) */ /* Comparison operators always return 0 or 1 */ int r = (5 > 3); /* r = 1 */ int s = (5 < 3); /* s = 0 */
💡
C99 stdbool.h
C99 added #include <stdbool.h> which gives you bool, true, and false — but they are just macros for int, 1, and 0. The underlying mechanics are identical.
🌍 Booleans in conditional logic

Every if-statement in C evaluates to an integer under the hood. Understanding that lets you write compact, clear conditions.

int logged_in = 1;   /* acts as true */
int is_admin  = 0;   /* acts as false */

if (logged_in)     printf("Welcome back!\n");
if (!is_admin)     printf("Standard access.\n");
if (0)             printf("Never prints.\n");

Topic 2

The Most Common Bug in C — == vs =

In Progress

Run this. The output may surprise you. Look closely at line 4.

= assigns. == compares. They are completely different.

x = 5 stores the value 5 into x. It is an assignment — it changes a variable.

x == 5 checks whether x equals 5 and evaluates to 1 (true) or 0 (false). It never changes x.

Writing if (x = 5) instead of if (x == 5) assigns 5 to x and then evaluates the result (5, which is non-zero — true). The condition will always be true, which is rarely what you want.

= vs ==
int x = 10; /* ASSIGNMENT: stores 5 in x */ x = 5; printf("%d\n", x); /* 5 */ /* COMPARISON: checks equality, x is unchanged */ int result = (x == 5); printf("%d\n", result); /* 1 (true) */ printf("%d\n", x); /* 5, still 5 */ /* THE BUG: assignment inside if */ if (x = 0) /* assigns 0 to x, then tests 0 → false! */ printf("never\n"); printf("%d\n", x); /* x is now 0 — silently changed! */
⚠
Most Common C Bug
Using = instead of == in an if condition. The compiler may not warn you. The program runs but gives wrong answers. Always double-check comparisons use ==.
🌍 Yoda conditions — a defensive technique

Some programmers flip the comparison to put the literal on the left: if (5 == x). If you accidentally type = instead of ==, the compiler errors immediately because you can't assign to a literal.

if (x = 5)    /* compiles, silent bug */
if (5 = x)    /* COMPILE ERROR — catches the typo */
if (5 == x)   /* correct defensive style */

Topic 3

Comparison Operators — == != < > <= >=

In Progress

Run this. Every comparison operator returns exactly 1 (true) or 0 (false).

Six comparison operators, all return 0 or 1

C has six comparison operators. All of them evaluate to the integer 1 when the comparison is true and 0 when false. This means you can store, print, or use them in arithmetic like any other integer.

All Six Comparison Operators
int a = 5, b = 3; a == b → 0 /* equal to */ a != b → 1 /* not equal to */ a > b → 1 /* greater than */ a < b → 0 /* less than */ a >= b → 1 /* greater than or equal to */ a <= b → 0 /* less than or equal to */ /* Return value is always 0 or 1 */ printf("%d\n", 10 >= 10); /* 1 — equal satisfies >= */ printf("%d\n", 3 != 3); /* 0 — they ARE equal */
⚠
No chaining comparisons
1 < x < 10 does NOT check if x is between 1 and 10. C evaluates left to right: (1 < x) gives 0 or 1, then it compares that against 10 — always true. Use x > 1 && x < 10 instead.
🌍 Comparisons drive every decision

Every validation, threshold check, and boundary test in real programs reduces to one of these six operators.

int temperature = 38;
int heart_rate  = 110;

if (temperature >= 38)   printf("Fever detected.\n");
if (heart_rate  > 100)   printf("Elevated heart rate.\n");
if (temperature == 37)   printf("Normal temp.\n");
if (heart_rate  != 72)   printf("Not resting rate.\n");

Topic 4

Logical Operators — && || !

In Progress

Run this. Three operators that combine or flip boolean values.

AND, OR, NOT — combining conditions

&& (AND) — both conditions must be true. If the left side is false, C does not evaluate the right side at all — this is called short-circuit evaluation.

|| (OR) — at least one condition must be true. If the left side is already true, the right side is skipped.

! (NOT) — flips true to false and false to true. !0 gives 1. !1 gives 0. !42 gives 0 (any non-zero becomes 0).

Logical Operators
int a = 1, b = 0; a && b → 0 /* AND: both must be true */ a || b → 1 /* OR: at least one true */ !a → 0 /* NOT: flips the value */ !b → 1 /* Short-circuit examples */ 0 && (x/0) /* right side never evaluates */ 1 || (x/0) /* right side never evaluates */ /* Combining */ int age = 25, has_id = 1; if (age >= 18 && has_id) printf("Entry allowed\n");
🌍 Login validation with logical operators

Real authentication logic always combines multiple conditions using logical operators.

int username_ok = 1, password_ok = 1, account_active = 1;

if (username_ok && password_ok && account_active)
    printf("Login successful\n");
else if (!account_active)
    printf("Account suspended\n");
else
    printf("Invalid credentials\n");

Topic 5

What Counts as True and False — Edge Cases

In Progress

Run this. Some of these results may be counterintuitive.

False is only zero. Everything else is true.

The rule is strict and simple: exactly zero is false. Every other integer value — negative, large, small — is true. This includes -1, 100, 0.1 (if stored as non-zero int), and even results of expressions like (5 > 3) which equals 1.

Beginners sometimes expect -1 to be false (like some other languages). In C it is not. Only 0 is false.

Truthiness in C
/* FALSE — only these */ if (0) /* never runs */ if (0.0) /* never runs */ /* TRUE — all of these */ if (1) /* runs */ if (-1) /* runs */ if (100) /* runs */ if (-0.1) /* runs (non-zero float) */ if (0+1) /* runs (evaluates to 1) */ /* Comparison returns 0 or 1 — both usable */ int pass = (score >= 60); /* 1 if passed, 0 if not */ if (pass) printf("Passed!\n");
🌍 Return values as true/false

Many C functions return 0 for success and non-zero for error — or vice versa. Knowing that non-zero means true lets you test them directly.

int items_in_cart = 3;
int payment_confirmed = 1;

/* Use the value directly as a boolean */
if (items_in_cart)
    printf("Cart has items: %d\n", items_in_cart);
if (payment_confirmed)
    printf("Payment confirmed.\n");

Topic 6

Combining Conditions — Ranges and Multi-Part Tests

In Progress

Run this. Multiple conditions combined into one test using && and ||.

Range checks and multi-part conditions

The most common use of && is a range check: testing that a value falls between two boundaries. You cannot write 1 < x < 10 in C — instead you write x > 1 && x < 10.

Parentheses matter. && has higher precedence than ||, so a || b && c means a || (b && c). When combining both, always add parentheses to make intent explicit.

Combining Conditions Correctly
int x = 15; /* Range check — correct C way */ if (x > 10 && x < 20) printf("In range\n"); /* prints */ /* WRONG: chaining doesn't work in C */ /* if (10 < x < 20) — always true! */ /* Multiple OR conditions */ if (x == 5 || x == 10 || x == 15) printf("Exact match\n"); /* prints */ /* Precedence: && before || */ if (x > 0 || x < -5 && x != 3) /* && runs first */ printf("Complex condition\n"); /* Better: explicit parentheses */ if ((x > 0) || (x < -5 && x != 3)) printf("Clear intent\n");
🌍 Grade classification with combined conditions

Range checks with && are the standard pattern for classifying values into bands.

int score = 82;

if      (score >= 90)              printf("A\n");
else if (score >= 80 && score < 90) printf("B\n");
else if (score >= 70 && score < 80) printf("C\n");
else if (score >= 60 && score < 70) printf("D\n");
else                                printf("F\n");

Topic 7

Truth Tables — Predicting Logical Expressions

In Progress

Run this — all 4 combinations of two boolean inputs, through AND and OR.

Truth tables let you predict any logical expression

A truth table maps every possible combination of inputs to the output. With two inputs (A and B), there are always exactly 4 rows: FF, FT, TF, TT.

The pattern to memorize: AND is strict — both must be true. OR is lenient — either one is enough. NOT is simple — one input, opposite output.

Truth Table — AND, OR, NOT
/* A B | A&&B | A||B | !A */ /* 0 0 | 0 | 0 | 1 */ /* 0 1 | 0 | 1 | 1 */ /* 1 0 | 0 | 1 | 0 */ /* 1 1 | 1 | 1 | 0 */ /* AND: only 1 row is true (bottom row) */ /* OR: only 1 row is false (top row) */ /* NOT: output opposite to input */
💡
Memory trick
AND is strict — only 1 true row out of 4. OR is lenient — only 1 false row out of 4.
🌍 Access control from first principles

Every access control system — file permissions, feature flags, subscription tiers — is just a truth table applied to real conditions.

int premium = 1, verified = 0;

/* Only premium AND verified can access */
if (premium && verified)     printf("Full access\n");

/* Premium OR verified gets partial access */
if (premium || verified)     printf("Partial access\n");

/* NOT premium = free tier */
if (!premium)                printf("Free tier\n");
