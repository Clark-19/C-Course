Chapter 12

Break & Continue

break and continue give you fine-grained control over what a loop does on any given iteration. Instead of waiting for the condition to expire naturally, you decide exactly when to exit early or skip ahead — two tools that turn rigid loops into precise, programmable logic.

5 Topics break · continue · nested · filtering · patterns
Topic 1

The break Statement — Exit Immediately

In Progress

Run this. The loop was set for 10 iterations — watch how many actually run.

break exits the loop immediately — no remaining iterations run

When C encounters break inside a loop body, it immediately jumps to the first statement after the loop's closing brace. The condition is never checked again. The update expression never runs. The remaining iterations are cancelled completely.

break is most useful for search loops — when you find what you are looking for, there is no reason to keep checking. It is also the mechanism that exits switch cases and while(1) infinite loops.

break — Exit Pattern
for (int i = 0; i < 100; i++) { if (/* found what we need */) { break; /* exit loop immediately */ } /* this only runs if break was not hit */ } /* execution resumes here after break */ /* Common use: search */ int found = -1; for (int i = 0; i < size; i++) { if (arr[i] == target) { found = i; break; /* no point checking further */ } }
💡
break only exits one loop
If you are in a nested loop, break only exits the innermost one. The outer loop continues normally. To exit multiple levels at once, you need a flag variable or a different approach — Topic 4 covers this in detail.
🌍 Input validation — stop processing on bad data

In data processing, break lets a loop stop as soon as it encounters an invalid value, preventing further computation on corrupted input.

int data[8] = {12, 45, -1, 33, 7, 99, 4, 22};
int valid_count = 0;

for (int i = 0; i < 8; i++) {
    if (data[i] < 0) {
        printf("Invalid value at index %d\n", i);
        break;          /* stop processing */
    }
    valid_count++;
}

printf("Valid entries: %d\n", valid_count);

Topic 2

The continue Statement — Skip This Iteration

In Progress

Run this. The loop runs 10 times but some iterations are silent. Observe which ones print.

continue skips the rest of this iteration — the loop still runs

When C encounters continue inside a loop body, it skips all remaining statements in that iteration and jumps directly to the update expression (in a for loop) or back to the condition check (in a while loop). The loop does not exit — it just skips the current pass and continues with the next.

This makes continue ideal for filtering — processing only elements that meet a condition while ignoring the rest, without breaking the loop's structure.

continue — Skip Pattern
for (int i = 0; i < 10; i++) { if (/* skip this one */) { continue; /* jumps to i++ then condition check */ } /* only runs when continue was NOT hit */ printf("%d\n", i); } /* Filter pattern — process only qualifying elements */ for (int i = 1; i <= 20; i++) { if (i % 2 == 0) continue; /* skip evens */ printf("%d is odd\n", i); /* only runs for odds */ }
⚠
continue in while loops — update must come before continue
In a while loop, the update (e.g. i++) is inside the body. If continue fires before the update, the counter never increments — causing an infinite loop. Always write the update before calling continue in a while loop body.
🌍 Skipping invalid records in a dataset

continue is how data pipelines skip corrupted or out-of-range entries without stopping the entire batch — the processing continues on the remaining valid records.

int readings[10] = {22, -99, 18, 255, 31, -1, 27, 19, 14, 300};
int valid_sum = 0, valid_count = 0;

for (int i = 0; i < 10; i++) {
    if (readings[i] < 0 || readings[i] > 100) {
        continue;       /* skip invalid sensor readings */
    }
    valid_sum += readings[i];
    valid_count++;
}

printf("Average: %d\n", valid_sum / valid_count);

Topic 3

break and continue Together

In Progress

Run this. Both keywords appear in the same loop — trace exactly what each one does.

break stops — continue skips. They are opposites with different scopes

continue affects only the current iteration — it skips the rest of this pass, then the loop continues normally. break affects the entire loop — it terminates all remaining iterations permanently. Both apply to the innermost enclosing loop only.

Used together: continue filters which elements you process, while break determines when you stop. A common pattern is: skip certain values with continue, and break when a stopping condition is met.

break vs continue — Side by Side
/* Using both: skip evens, stop at first multiple of 9 */ for (int i = 1; i <= 20; i++) { if (i % 2 == 0) continue; /* skip even numbers entirely */ if (i % 9 == 0) { printf("Multiple of 9 found: %d\n", i); break; /* done — stop the loop */ } printf("%d\n", i); /* prints odd non-multiples of 9 */ } /* continue → loop goes on, just skips remaining body for this i */ /* break → loop ends, nothing after this executes */
🌍 Scanning a list — skip irrelevant, stop on match

Many search routines combine both: continue to bypass entries that cannot be the answer, and break once the target is confirmed — minimizing wasted work.

int prices[8] = {50, 0, 120, 0, 85, 200, 0, 99};
int budget = 100, best = -1;

for (int i = 0; i < 8; i++) {
    if (prices[i] == 0) continue;    /* skip unavailable */
    if (prices[i] > budget) continue; /* skip over budget */
    best = prices[i];
    break;                            /* first match is enough */
}

printf("Best price found: %d\n", best);

Topic 4

break in Nested Loops — Only the Innermost

In Progress

Run this nested loop with break. Count which rows complete and which terminate early.

break only exits one loop — the innermost one that contains it

In nested loops, break only exits the loop whose body directly contains the break statement. The outer loop does not know break fired — it continues its next iteration normally, which re-enters the inner loop fresh.

To exit multiple levels at once, use a flag variable: set a boolean flag inside the inner loop, check it in the outer loop's condition, and break both. This is the standard C pattern for multi-level exits since C has no labeled break.

Breaking Multiple Levels — Flag Pattern
/* break only exits inner loop */ for (int r = 0; r < 3; r++) { for (int c = 0; c < 5; c++) { if (c == 2) break; /* only inner exits — outer keeps running */ } printf("Row %d still runs\n", r); /* prints 3 times */ } /* Flag pattern to exit both loops */ int done = 0; for (int r = 0; r < 3 && !done; r++) { for (int c = 0; c < 5; c++) { if (r == 1 && c == 2) { done = 1; break; } } } printf("Stopped at row 1, col 2\n");
💡
C has no labeled break — use a flag variable
Some languages like Java have break label; to exit specific outer loops. C does not. The idiomatic C solution is a flag: int found = 0; set inside the inner loop, then check && !found in the outer loop condition. Clean and readable.
🌍 2D grid search — finding a target cell

Searching a 2D array for a specific value uses a flag to break both loops once the cell is found — the row/column indices survive for use after the loop.

int grid[3][4] = {
    {2,  7, 14,  1},
    {9, 99,  3, 11},
    {6,  4, 18,  5}
};
int target = 99, tr = -1, tc = -1, found = 0;

for (int r = 0; r < 3 && !found; r++) {
    for (int c = 0; c < 4; c++) {
        if (grid[r][c] == target) {
            tr = r; tc = c; found = 1; break;
        }
    }
}
printf("Found at [%d][%d]\n", tr, tc);  /* [1][1] */

Topic 5

Filtering Patterns — Real Uses of break & continue

In Progress

Run this. It uses both break and continue to process a list — notice how few iterations actually do the main work.

Filtering is about deciding per-iteration: skip, process, or stop

Every loop that uses break or continue implements a decision at each iteration. These are not complicated concepts — they are simple two-branch decisions: "should I skip this?" (continue) and "should I stop now?" (break). The power comes from combining them with conditions.

Think in terms of a filter funnel: each element enters the loop, gets checked against guard conditions (continue to skip), does the main work, then optionally stops (break). This pattern appears in every non-trivial C program that processes data.

The Filter Funnel Pattern
for (int i = 0; i < n; i++) { /* Guard 1: skip invalid entries */ if (data[i] == INVALID) continue; /* Guard 2: skip out-of-range */ if (data[i] < MIN || data[i] > MAX) continue; /* Main work — only runs for valid, in-range items */ process(data[i]); /* Stopping condition */ if (result_found) break; } /* Every guard condition uses the same structure: - if (reject condition) continue; - if (stop condition) break; - main logic at the bottom (least indented = clearest) */
💡
Guard conditions first — main logic at the bottom
Putting continue guards at the top of a loop body reduces nesting and makes the main logic easy to find. The alternative — wrapping the main logic in a large if block — leads to deeply nested, hard-to-read code. Guards first, work last.
🌍 Number analysis — classify and collect

Statistical routines use continue to filter bad data and break to cap collection size — making them robust against both corrupted inputs and oversized datasets.

int raw[12] = {14, -5, 8, 0, 23, 7, -1, 11, 0, 6, 17, 4};
int primes[5], count = 0;

for (int i = 0; i < 12 && count < 5; i++) {
    if (raw[i] <= 1) continue;       /* skip non-positive */

    /* Simple primality check */
    int is_prime = 1;
    for (int d = 2; d * d <= raw[i]; d++) {
        if (raw[i] % d == 0) { is_prime = 0; break; }
    }

    if (!is_prime) continue;          /* skip composites */
    primes[count++] = raw[i];
}

for (int i = 0; i < count; i++) printf("%d ", primes[i]);
