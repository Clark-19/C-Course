Chapter 17

Structs & Enums

C gives you primitive types — int, float, char. Structs let you invent your own types. A Student, a Point, a Color — any grouping of related data becomes a first-class type you can declare, copy, and pass around like a built-in. Enums make your code read like English instead of magic numbers. Together, these two tools are how real C programs organize complex data.

Topic 1

What Is a Struct?

In Progress

Run this. A struct groups related variables under one name — compile it and observe the output.

A struct is a custom type that groups related variables into a single unit

Without structs, a student record needs separate variables: char name[50], int age, float grade — all unconnected. A struct bundles them: one Student s variable holds all three. The struct definition describes the shape; the struct variable is the actual data.

Structs don't allocate memory. The struct Student { ... }; definition is just a blueprint. Memory is only allocated when you declare a variable: struct Student s;.

Struct Definition & Declaration
/* Step 1: define the shape (no memory yet) */ struct Student { char name[50]; /* member 1 */ int age; /* member 2 */ float grade; /* member 3 */ }; /* semicolon required after closing brace */ /* Step 2: declare a variable of that type */ struct Student s; /* now memory is allocated */ /* Or combine both steps */ struct Student s2 = {"Alice", 20, 92.5};
⚠
Missing the semicolon after } is the most common struct bug
struct Student { int age; } without the final ; causes a cryptic compiler error on the next line. Every struct definition ends with }; — the semicolon is part of the statement.
🌍 Real-world context

Every C graphics library, game engine, and networking stack uses structs to represent entities — a Point, a Packet, a Vertex. They are the foundation of every custom data type in C.

/* OpenGL-style point struct */
struct Vec3 {
    float x, y, z;
};

struct Vec3 position = {1.0f, 0.0f, -5.0f};
struct Vec3 camera   = {0.0f, 1.0f,  0.0f};

Topic 2

Declaring and Initializing Structs

In Progress

Run this. Three ways to initialize a struct — compile and see all three produce output.

Three ways to put values into a struct — each has its place

Initializer list = {"Alice", 20, 92.5} sets all members at declaration time, in order. Member-by-member assignment sets each field individually after declaration — useful when values come from user input or calculations. Designated initializers (C99+) use .member = value syntax and can appear in any order.

Uninitialized struct members contain garbage values — the same rule as any uninitialized variable. Always initialize before reading.

Three Initialization Styles
struct Point { int x; int y; }; /* 1. Initializer list — position-based, must match member order */ struct Point a = {3, 7}; /* 2. Member-by-member — can set in any order, any time */ struct Point b; b.x = 10; b.y = 20; /* 3. Designated initializer (C99) — named, any order */ struct Point c = { .y = 5, .x = 1 }; /* 4. Struct assignment — copies all members at once */ struct Point d = a; /* d.x = 3, d.y = 7 */
💡
Struct assignment copies the entire value
struct Point d = a; copies every member from a into d. They are independent after that — changing d.x does not affect a.x. This is unlike arrays, which cannot be assigned this way.
🌍 Real-world context

Designated initializers are essential in embedded C where you want to set only certain fields and leave others at zero — common for hardware register structs with many fields.

/* Only configure what you need — the rest default to 0 */
struct UARTConfig cfg = {
    .baud_rate = 115200,
    .parity    = NONE
    /* .stop_bits, .flow_control stay 0 */
};

Topic 3

Accessing Members — the . Operator

In Progress

Run this. The dot operator reads and writes individual members — observe both get and set patterns.

The dot operator gives you direct access to any member of a struct variable

variable.member works both for reading and writing. s.age reads the age field. s.age = 21 updates it. The dot is the bridge between the struct variable and its individual pieces of data.

Members are independent — updating s.grade has no effect on s.name or s.age. Each member behaves exactly like the variable type it is declared as inside the struct.

Dot Operator — Read and Write
struct Student { char name[50]; int age; float grade; }; struct Student s = {"Bob", 19, 88.0}; /* READ — use in expressions */ printf("%s\n", s.name); /* Bob */ printf("%d\n", s.age); /* 19 */ printf("%.1f\n", s.grade); /* 88.0 */ /* WRITE — assign like any variable */ s.age = 20; s.grade = 95.5; /* Use in arithmetic */ s.grade = s.grade + 5.0; /* 100.5 */
⚠
You cannot assign a string to a char array member with =
s.name = "Alice"; is illegal because arrays cannot be assigned. Use strcpy(s.name, "Alice"); from <string.h> instead. You can only use = for string members during initialization: struct Student s = {"Alice", 20, 90.0};
🌍 Real-world context

The dot operator is used constantly in C programs — reading config fields, updating state, passing parts of a struct to functions. It is the primary way to interact with custom data types.

struct Config {
    int   width;
    int   height;
    float scale;
};

struct Config cfg = {1920, 1080, 1.0f};
cfg.scale = 2.0f;   /* hi-DPI mode */

int pixels = cfg.width * cfg.height;
printf("%d total pixels\n", pixels);

Topic 4

Nested Structs

In Progress

Run this. A struct can contain another struct as a member — compile and follow the dot chain.

Structs can contain other structs — access the inner members with chained dots

If a struct member is itself a struct, you chain the dot operator: student.address.city. Each dot steps one level deeper into the nested structure. There is no limit to nesting depth, but more than two or three levels usually signals a design problem.

Nested structs are useful when a sub-concept has its own coherent identity. An Address makes sense as its own struct — it has street, city, zip — and then a Student has an address member of type struct Address.

Nested Struct Access
struct Date { int day; int month; int year; }; struct Student { char name[50]; struct Date dob; /* nested: Date inside Student */ }; struct Student s; strcpy(s.name, "Ana"); s.dob.day = 15; /* dot chain: s → dob → day */ s.dob.month = 8; s.dob.year = 2003; printf("%s born: %d/%d/%d\n", s.name, s.dob.day, s.dob.month, s.dob.year);
💡
Nested struct initialization with nested braces
struct Student s = {"Ana", {15, 8, 2003}}; — the outer braces hold the Student initializer, and the inner braces hold the Date initializer. Each nested struct gets its own set of braces in the initializer list.
🌍 Real-world context

Nested structs appear in every network and file format library. A TCP packet struct contains an IP header struct, which contains a source and destination address struct — each level represents a distinct abstraction.

struct IPAddr  { unsigned char bytes[4]; };
struct IPHeader {
    struct IPAddr src;
    struct IPAddr dst;
    int           ttl;
};
/* Access: packet.header.src.bytes[0] */

Topic 5

Arrays of Structs

In Progress

Run this. An array where each element is a complete struct — compile and see the loop iterate over records.

An array of structs stores multiple records — index with [i], then access members with .

Declare like any array: struct Student roster[30]; gives you 30 Student slots. Access a specific record by index first: roster[0] is the first Student. Then dot into it: roster[0].grade is that student's grade.

You can initialize an array of structs at declaration: each element gets its own { } initializer separated by commas. Looping with for over an array of structs is one of the most common C patterns for working with collections of records.

Array of Structs — Declare, Initialize, Loop
struct Student { char name[30]; float grade; }; /* Initialize all at once */ struct Student class[3] = { {"Alice", 92.0}, {"Bob", 78.5}, {"Carol", 88.0} }; /* Loop and access */ for (int i = 0; i < 3; i++) { printf("%s: %.1f\n", class[i].name, class[i].grade); } /* Access one specific member */ class[1].grade = 80.0; /* update Bob's grade */
💡
The pattern is: array[index].member
roster[i].grade — index into the array first to pick which record, then dot to pick which field. Never roster.grade[i] — that is not valid syntax and does not mean what you think.
🌍 Real-world context

Database-less record management in embedded systems and simple utilities typically uses arrays of structs — a fixed-size contact book, a sensor log, a configuration table.

struct Contact {
    char  name[50];
    char  phone[15];
};

struct Contact book[100];
int count = 0;

/* Add a contact */
strcpy(book[count].name,  "Ana Reyes");
strcpy(book[count].phone, "09171234567");
count++;

Topic 6

Pointers to Structs — the -> Operator

In Progress

Run this. When you have a pointer to a struct, -> is the access operator — compile and observe both . and -> in action.

Use . for struct variables; use -> for pointers to structs

When you have a pointer struct Student *p, accessing members requires dereferencing first: (*p).age. The arrow operator p->age is shorthand for exactly that — dereference the pointer, then access the member. They are identical in meaning, but -> is cleaner and what every C programmer uses.

The rule is simple: variable → dot, pointer → arrow. Mixing them up — using . on a pointer — causes a compiler error.

Dot vs Arrow — The Complete Rule
struct Student { char name[50]; int age; }; struct Student s = {"Dan", 22}; /* a variable */ struct Student *p = &s; /* a pointer */ /* dot — only for direct variables */ printf("%s\n", s.name); /* "Dan" */ /* arrow — for pointers (shorthand for (*p).name) */ printf("%s\n", p->name); /* "Dan" — same result */ /* WRITE through pointer */ p->age = 23; /* modifies s.age too — same memory */ printf("%d\n", s.age); /* 23 */ /* These are identical */ (*p).age = 24; /* long form */ p->age = 24; /* short form — always prefer this */
⚠
Using . on a pointer is a compiler error
p.age when p is struct Student *p will not compile. The compiler tells you the left-hand side must be a struct, not a pointer. Use p->age. The compiler error is actually helpful here — it forces the right syntax.
🌍 Real-world context

Linked lists — one of the most important data structures — are built entirely on struct pointers and the arrow operator. Every node points to the next node, and -> is how you traverse the chain.

struct Node {
    int         value;
    struct Node *next;
};

struct Node *current = head;
while (current != NULL) {
    printf("%d\n", current->value);
    current = current->next;
}

Topic 7

Passing Structs to Functions

In Progress

Run this. A struct passed by value is copied — changes inside the function don't affect the original. Compile and verify.

Structs pass by value (copy) — use a pointer parameter to modify the original

Passing struct Student s to a function copies the entire struct. The function gets its own independent copy. Changes inside the function are invisible to the caller. This is correct when you want read-only access — but for large structs, copying is wasteful in memory and time.

Pass a pointer struct Student *s to let the function modify the original. Inside the function, use s->member to access fields. This is also more efficient — only the address (8 bytes) is copied, not the entire struct.

Pass by Value vs Pass by Pointer
struct Student { char name[50]; float grade; }; /* Pass by VALUE — caller's struct unchanged */ void printStudent(struct Student s) { printf("%s: %.1f\n", s.name, s.grade); s.grade = 0; /* only changes the local copy */ } /* Pass by POINTER — can modify the original */ void applyBonus(struct Student *s, float bonus) { s->grade += bonus; /* modifies caller's struct */ } /* Return a struct by value */ struct Student makeStudent(char *name, float grade) { struct Student s; strcpy(s.name, name); s.grade = grade; return s; /* entire struct is returned */ }
💡
Prefer pointer parameters for structs larger than a few bytes
Copying a struct with 10 fields is expensive if done thousands of times. Use const struct Student *s when you want pointer efficiency but don't need to modify: the const prevents accidental writes while avoiding the copy.
🌍 Real-world context

Functions that build and return structs — called factory functions — are a clean pattern for creating records. Rather than initializing a struct manually each time, you call a function that returns a ready-to-use value.

struct Vec2 makeVec2(float x, float y) {
    struct Vec2 v = {x, y};
    return v;
}

float magnitude(const struct Vec2 *v) {
    return sqrt(v->x * v->x + v->y * v->y);
}

Topic 8

typedef — Cleaner Struct Names

In Progress

Run this. With typedef, struct Student becomes just Student — compile and compare both declaration styles.

typedef creates a new name for an existing type — commonly used to drop the struct keyword

typedef struct Student Student; creates an alias so you can write Student s; instead of struct Student s;. Both refer to the same thing — typedef just creates a shorter alias. The most common pattern combines the struct definition and typedef in one block.

typedef works for any type, not just structs — you can alias int to Integer or unsigned char to Byte. For structs it is especially valuable because it removes the repetitive struct keyword from every usage.

typedef Patterns
/* Pattern 1: define then typedef separately */ struct Student { char name[50]; int age; }; typedef struct Student Student; /* Pattern 2: combine in one statement (most common) */ typedef struct { char name[50]; int age; float grade; } Student; /* Student is now the type name */ /* Usage — no more 'struct' keyword needed */ Student s = {"Eva", 21, 94.0}; Student *p = &s; /* Works in function parameters too */ void print(Student s) { printf("%s\n", s.name); } void update(Student *s, float grade) { s->grade = grade; }
💡
The anonymous struct pattern is the standard in modern C code
Most C code you will encounter uses typedef struct { ... } TypeName; with no tag inside the struct keyword. The tag is only needed when the struct refers to itself (like a linked list node: typedef struct Node { int v; struct Node *next; } Node;).
🌍 Real-world context

typedef for primitive types is common in cross-platform C to guarantee fixed sizes — int can be 16 or 32 bits depending on the system, but int32_t (defined via typedef in <stdint.h>) is always exactly 32 bits.

#include <stdint.h>

/* These are defined in stdint.h via typedef */
typedef unsigned char  uint8_t;   /* always 8 bits  */
typedef unsigned int   uint32_t;  /* always 32 bits */

uint32_t sensor_reading = 0xDEADBEEF;

Topic 9

Enums — Named Integer Constants

In Progress

Run this. An enum gives integer constants readable names — compile and see what value each name maps to.

An enum is a set of named integer constants — it replaces magic numbers with meaningful names

Without enums, you might write if (day == 1) — and later wonder: is Monday 1 or 0? An enum names these values: MONDAY, TUESDAY, etc. The compiler assigns integers starting from 0 automatically, or you can assign values manually. Using the names makes the code self-documenting.

Enum values are just int constants. C doesn't enforce type safety on them — you can assign any integer to an enum variable. But the named constants make intent clear to every person reading the code.

Enum Declaration and Values
/* Basic enum — auto-numbered from 0 */ enum Day { MON, /* = 0 */ TUE, /* = 1 */ WED, /* = 2 */ THU, /* = 3 */ FRI, /* = 4 */ SAT, /* = 5 */ SUN /* = 6 */ }; /* Use as a variable type */ enum Day today = WED; printf("%d\n", today); /* prints 2 */ /* Custom starting value */ enum Status { OK = 200, NOT_FOUND = 404, ERROR = 500 }; enum Status code = OK; printf("%d\n", code); /* prints 200 */
💡
Enum constants are global — they don't need the enum name as a prefix
Write enum Day d = MON;, not d = Day.MON. The constant MON is visible everywhere once the enum is defined. This differs from languages like Java or C++ where you qualify with the type name. It also means two enums cannot share a constant name in the same scope.
🌍 Real-world context

Enums are everywhere in C system headers — file open modes, socket types, signal numbers. They replace inscrutable integer constants with names that make the code read like a specification.

/* From a real embedded project */
enum PinState { LOW = 0, HIGH = 1 };
enum PinMode  { INPUT, OUTPUT, INPUT_PULLUP };

void digitalWrite(int pin, enum PinState state);
void pinMode(int pin, enum PinMode mode);

Topic 10

Using Enums for State and Flags

In Progress

Run this. Enums pair naturally with switch — compile and see state-based output driven by enum values.

Enums model state machines and option sets — switch makes the logic readable

The most common enum pattern is a state machine — a variable holds the current state, and a switch statement decides what to do based on it. The combination of enum + switch is cleaner than chains of if/else if with raw integers because each case label is named, not numbered.

Enums can also represent flags by assigning power-of-two values (1, 2, 4, 8) — multiple flags can then be combined with bitwise OR and tested with bitwise AND. This is an advanced pattern used in file permissions, UI option sets, and protocol fields.

Enum + Switch State Machine
typedef enum { IDLE, RUNNING, PAUSED, STOPPED } State; State current = IDLE; void describe(State s) { switch (s) { case IDLE: printf("Waiting for input\n"); break; case RUNNING: printf("Processing...\n"); break; case PAUSED: printf("Paused — resume?\n"); break; case STOPPED: printf("Done.\n"); break; } } describe(current); /* Waiting for input */ current = RUNNING; describe(current); /* Processing... */
💡
Using enum in switch also enables compiler warnings for unhandled cases
When you switch on an enum and miss a case, many compilers warn: "enumeration value 'PAUSED' not handled in switch." This is a safety net — the compiler forces you to handle every possible state. That warning disappears when you add a default case, so only use default when you genuinely don't care about the rest.
🌍 Real-world context

Traffic light controllers, vending machine logic, game character AI, network connection handling — all are implemented as state machines. The enum gives each state a name; the switch determines what happens in each state.

typedef enum { RED, YELLOW, GREEN } Light;

Light next(Light current) {
    switch (current) {
        case RED:    return GREEN;
        case GREEN:  return YELLOW;
        case YELLOW: return RED;
    }
    return RED;
}

Topic 11

Unions — Shared Memory

In Progress

Run this. A union stores one value at a time in shared memory — compile and see how writing one member overwrites the others.

A union allocates one block of memory shared by all members — only one member is valid at a time

A union looks like a struct — same syntax, same member access — but all members share the same memory location. The union is only as large as its largest member. Writing to u.i overwrites the bytes used by u.f. Reading u.f after writing u.i gives undefined behavior — it's the caller's responsibility to track which member is active.

Unions are used for memory-efficient variants (a value that could be int or float), byte-level access to multi-byte data, and protocol parsing where the same bytes might be interpreted as different types.

Union Declaration and Size
union Data { int i; /* 4 bytes */ float f; /* 4 bytes */ char c; /* 1 byte */ }; /* sizeof(union Data) == 4 — largest member size */ union Data u; u.i = 42; printf("%d\n", u.i); /* valid: 42 */ /* u.f is now garbage — same bytes, wrong interpretation */ u.f = 3.14f; printf("%.2f\n", u.f); /* valid: 3.14 */ /* u.i is now garbage */ /* vs struct: each member has its own memory */ /* sizeof(struct Data with same members) == 9+ */
⚠
Reading the wrong union member gives garbage — C won't warn you
Write u.i = 5 then read u.f — you get whatever 5 looks like as a float bit pattern, which is not 5.0. The C standard calls this undefined behavior. In practice, use an enum tag alongside a union (a "tagged union") to track which member is currently valid.
🌍 Real-world context

Tagged unions — a union paired with an enum tag — are the C idiom for variant types. JSON parsers, scripting language interpreters, and compiler AST nodes all use this pattern to represent a value that can be one of several different types.

typedef enum { INT_VAL, FLOAT_VAL, STR_VAL } ValType;

typedef struct {
    ValType type;
    union {
        int   i;
        float f;
        char *s;
    } data;
} Value;

Value v;
v.type   = INT_VAL;
v.data.i = 42;

if (v.type == INT_VAL) printf("%d\n", v.data.i);
